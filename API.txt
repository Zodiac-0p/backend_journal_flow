SERVER
http://127.0.0.1:8000

DJANGO ADMIN
http://127.0.0.1:8000/admin/

ADMIN CREDENTIALS
Use locally configured admin credentials. Do not commit real emails or passwords.

AUTH HEADER FOR PROTECTED APIS
Authorization: Bearer <access_token>

NOTES
- Use JSON body unless an endpoint says multipart/form-data.
- Replace IDs like {submission_id}, {file_id}, {author_id}, {user_id} with real IDs from previous responses.
- Most APIs require authentication because the project default permission is IsAuthenticated.
- Master data create/update/delete requires Editorial Manager or Super Admin.
- Master data DELETE is a soft delete: it sets is_active=false instead of removing database rows.
- Email notifications use the configured Django EMAIL_BACKEND.
- In development, emails are printed to the console unless EMAIL_BACKEND is changed in .env.

Minimum required fields:

  "username": "author1",
  "full_name": "Author One",
  "password": "StrongPass123"
}

Minimum required fields for reviewer registration:

  "full_name": "Reviewer One",

Notes:
- classification_ids is optional for normal user registration.
- classification_ids is required only when want_to_be_reviewer is true.
- Reviewer registration must include at least 4 active journal classifications.
- Sends an email verification OTP mail.
- Creates an in-app notification asking the user to verify email.
- User must verify email before login.

Submission Actions

62. Final Submit Manuscript
POST /api/journals/submissions/{submission_id}/submit/

Requirements:
- article_type selected
- required submission files uploaded
- title, abstract, keywords completed
- at least one author added
- open_access selected
- at least 4 classifications selected
- at least one additional information field completed
- ethics_accepted true

Result:
- manuscript_reference is generated automatically, for example ERX-117446.
- Active editor with the lowest active assigned submission count is assigned to assigned_editor.
- Status changes to under_editor_review.
- Sends article submission success email to the author with manuscript_reference and article title.
- Creates an in-app notification for the author.
- Sends new-submission assignment email to the assigned editor with manuscript_reference and article title.
- Creates an in-app notification for the assigned editor.

If required data is missing, the API returns:
HTTP 400 Bad Request
{
  "detail": "Complete all required fields before final submission.",
  "missing_requirements": {
    "article_type": "Select an article type.",
    "submission_files": {

    "title_abstract_keywords": {
      "message": "Complete title, abstract, and keywords.",
      "missing_fields": ["title", "abstract", "keywords"]
    },
    "author_details": "Add at least one author.",
    "open_access": "Select an open access option.",
    "classifications": {
      "message": "Select at least 4 active classifications.",
      "selected_count": 2,
      "required_count": 4
    },
    "additional_information": {
      "message": "Complete at least one additional information field.",

        "funding_information",

64. Resubmit Revised Manuscript
POST /api/journals/submissions/{submission_id}/resubmit/

Allowed only when the current submission status is:
- minor_revision
- major_revision

If the submission is not in one of these statuses, the API returns:
HTTP 400 Bad Request
{
  "detail": "Only submissions requiring minor or major revision can be resubmitted."
}

Testing note:
- Use the editor decision API to set the submission status to minor_revision or major_revision before testing this endpoint.
- On successful resubmission, the API creates a new submission version and changes the submission status back to submitted.
- Sends status-change email to the author.
- Creates an in-app notification for the author.
- Sends revised-submission email to the assigned editor.
- Creates an in-app notification for the assigned editor.

Body type:
multipart/form-data

Fields:
- manuscript_file: revised_manuscript.pdf
- revision_notes: Updated as requested.

PowerShell curl example:
curl.exe -X POST "http://127.0.0.1:8000/api/journals/submissions/1/resubmit/" `
  -H "Authorization: Bearer <access_token>" `
  -F "manuscript_file=@C:\path\to\revised_manuscript.pdf" `
  -F "revision_notes=Updated as requested."

67. Assign Reviewer To Article
POST /api/journals/submissions/{submission_id}/assign-reviewer/

Rules:
- Submission status must be submitted, under_editor_review, or under_peer_review.
- Use reviewer_id to assign one reviewer, or reviewer_ids to assign multiple reviewers.
- Each selected reviewer must belong to an active reviewer account.
- Reviewer must match at least one selected submission classification.
- On success, the submission status changes to under_peer_review (peer review stage).
- Sends reviewer-assignment email to each newly assigned reviewer.
- Creates an in-app notification for each newly assigned reviewer.
- Sends status-change email to the author when status changes.
- Creates an in-app status-change notification for the author.
- Each reviewer assignment starts with status pending.

Single reviewer request:

  "reviewer_id": 5
}

Multiple reviewer request:

  "reviewer_ids": [5, 6, 7]

73. Submit Reviewer Report
POST /api/journals/reviewer-assignments/{assignment_id}/submit-report/

Reviewer only.

Purpose:
- Submit the full reviewer questionnaire from a single page.
- The same endpoint can update an existing reviewer report.

Rules:
- Only the assigned reviewer can submit the report.
- The reviewer assignment must already be accepted.
- If ready_to_transfer_to_editor is true, the questionnaire fields and recommendation are required.
- When the report is transferred, the editor receives email and in-app notification.

Request:
{
  "review_report_complete": true,
  "ready_to_transfer_to_editor": true,
  "recommendation": "minor_revision",
  "reviewer_comments_to_author": "The manuscript is promising but needs minor revisions.",
  "confidential_comments_to_editor": "The methods are useful and the paper can move forward.",
  "paper_referee_confidence": "confident",
  "referee_suitability_rating": "100",
  "paper_quality_rating": "significant",
  "paper_value_rating": "minor_modifications",
  "suitable_for_different_journal": false,
  "content_original_work": true,
  "content_well_organised": true,
  "content_abstract_adequate": true,
  "content_technically_sound": true,
  "content_practical_application": true,
  "content_references_adequate": true,
  "presentation_explains_clearly": true,
  "presentation_methods_included": true,
  "presentation_demonstrates_value": true,
  "presentation_language_clear": true,
  "manuscript_classification": "paper"
}

Allowed values:
- recommendation: accept | reject | minor_revision | major_revision
- paper_referee_confidence: confident | not_able
- referee_suitability_rating: 100 | 75 | 50 | 25 | 0
- paper_quality_rating: excellent | significant | marginal | non_significant | erroneous_or_trivial
- paper_value_rating: worth_publishing | minor_modifications | major_modifications | not_worth_publishing
- manuscript_classification: review | paper | communication | technical_note

74B. Send Selected Reviewer Comments To Author
POST /api/journals/submissions/{submission_id}/send-review-comments/

Editor, Editorial Manager, or Super Admin only.

Purpose:
- Lets the editor select one or more completed reviewer reports and send the reviewer_comments_to_author content to the author by email.

Request:
{
  "review_report_ids": [1, 2]
}

Rules:
- All selected review reports must belong to the same submission.
- Only reports with ready_to_transfer_to_editor=true are allowed.
- At least one selected report must contain reviewer_comments_to_author text.
- The author receives one email containing the selected reviewer comments.
- The author also receives an in-app notification.

Success response:
{
  "message": "Reviewer comments sent to the author successfully.",
  "submission_id": 10,
  "sent_review_report_ids": [1, 2]
}

75. Submit Editor Decision
POST /api/journals/submissions/{submission_id}/editor-decision/

Editor, Editorial Manager, or Super Admin only.

Purpose:
- Apply the editor decision after at least one transferred reviewer report exists.

Request:
{
  "decision": "minor_revision",
  "editor_comment": ""
}

Allowed decision values:
- accepted
- rejected
- minor_revision
- major_revision

Rules:
- At least one transferred reviewer report is required.
- Submission must be under_editor_review or under_peer_review.
- On success, the submission status is updated and active reviewer assignments are closed.
- The author receives the standard submission status update email and in-app notification.

############################################################
SECTION 4: NOTIFICATIONS API
############################################################

BASE URL
http://127.0.0.1:8000/api/notifications/

Automatic Notification Events
- User registration: welcome email and in-app notification.
- Forgot password: OTP email and in-app notification.
- Reset password success: success email and in-app notification.
- Submission status changes: author email and in-app notification.
- Final submission: least-loaded editor assignment email and in-app notification.
- Reviewer assignment: reviewer email and in-app notification.
- Reviewer accept/reject response: editor email and in-app notification.
- Reviewer report submitted: editor email and in-app notification.
- Reviewer response overdue after 3 days: editor email and in-app notification.

Scheduled Notification Command

Run this command daily using cron, Windows Task Scheduler, or a background worker:

python manage.py notify_overdue_reviewer_assignments

Behavior:
- Finds active reviewer assignments with status pending.
- Only checks assignments older than 3 days by default.
- Skips assignments that already received an overdue reminder.
- Sends email and in-app notification to the assigned editor.
- If assigned_editor is empty, falls back to assigned_by.

Options:
python manage.py notify_overdue_reviewer_assignments --days 3
python manage.py notify_overdue_reviewer_assignments --dry-run

############################################################
SECTION 8: GAP ANALYSIS AND SUGGESTED NEXT APIS
############################################################

Current status after code review
- Most endpoints documented in Sections 1 to 7 already exist in the backend.
- The main missing work is now behavior completion, workflow restrictions, and a few useful editorial APIs.

Implemented endpoint behavior gaps to fix

1. Reset Password Success Email
Current code:
- Reset password creates an in-app notification.
- Reset password does not send the success email mentioned in Section 1.

Need:
- Send a password reset success email after POST /api/accounts/reset-password/ succeeds.

2. Editor Decision Comment Is Not Saved
Current code:
- POST /api/journals/submissions/{submission_id}/editor-decision/ accepts editor_comment.
- editor_comment is validated but not stored anywhere.

Need:
- Add a model field or decision history model so editor comments are saved and returned later.

3. Notification Read API Can Raise Server Error For Wrong ID
Current code:
- POST /api/notifications/{notification_id}/mark-read/ uses Notification.objects.get(...)
- Missing notifications are not handled safely.

Need:
- Return HTTP 404 with a clean JSON response when the notification does not exist or does not belong to the logged-in user.

4. Submission Workflow Needs Status Guards
Current code:
- Authors can patch files/authors/submission data even after submission.
- Withdraw does not restrict which statuses can be withdrawn.
- Submit does not block re-submitting already submitted or closed items.

Need:
- Restrict edit actions to draft and revision stages only.
- Restrict withdraw to allowed statuses only.
- Prevent final submit on already submitted/withdrawn/accepted/rejected/published records.

5. Classification Draft Save Rule Needs Clarification
Current code:
- PATCH submission with classification_ids requires at least 4 classifications immediately.
- This prevents saving a partial draft with 1 to 3 classifications.

Need:
- Choose one approach and keep API.txt aligned:
- Option A: allow partial draft saves and enforce 4 classifications only on final submit.
- Option B: keep current validation and clearly document that fewer than 4 classifications are rejected even in draft mode.
