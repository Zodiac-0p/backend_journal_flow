============================================================
PUBLICATION MANAGER BACKEND - API TEST DOCUMENT
============================================================

SERVER
http://127.0.0.1:8000

DJANGO ADMIN
http://127.0.0.1:8000/admin/

ADMIN CREDENTIALS
Use locally configured admin credentials. Do not commit real emails or passwords.

AUTH HEADER FOR PROTECTED APIS
Authorization: Bearer <access_token>

NOTES
- Use JSON body unless an endpoint says multipart/form-data.
- Replace IDs like {submission_id}, {file_id}, {author_id}, {user_id} with real IDs from previous responses.
- Most APIs require authentication because the project default permission is IsAuthenticated.
- Master data create/update/delete requires Editorial Manager or Super Admin.
- Master data DELETE is a soft delete: it sets is_active=false instead of removing database rows.

PUBLIC APIS
============================================================

1. Check Email
POST /api/accounts/check-email/

Request:
{
  "email": "author@example.com"
}

2. Register New User
POST /api/accounts/register/

Request:
{
  "email": "author@example.com",
  "username": "author1",
  "full_name": "Author One",
  "password": "StrongPass123",
  "phone": "9876543210",
  "affiliation": "ABC University",
  "organization": "ABC University",
  "job_title": "Research Scholar",
  "expertise": "Artificial Intelligence",
  "want_to_be_reviewer": true,
  "role_choice_id": 1,
  "discipline_ids": [1, 2]
}

Minimum required fields:
{
  "email": "author@example.com",
  "username": "author1",
  "full_name": "Author One",
  "password": "StrongPass123"
}

3. Login
POST /api/accounts/login/

Request:
{
  "email": "author@example.com",
  "password": "StrongPass123"
}

Save these response values:
- access
- refresh
- user.id

4. Refresh Access Token
POST /api/accounts/token/refresh/

Request:
{
  "refresh": "<refresh_token>"
}

5. Forgot Password
POST /api/accounts/forgot-password/

Request:
{
  "email": "author@example.com"
}

Expected response is generic for security:
{
  "message": "If an account exists for this email, an OTP has been sent."
}

Notes:
- OTP expires after PASSWORD_RESET_OTP_EXPIRY_MINUTES from .env.
- Current throttle defaults: 3 requests/hour.

6. Reset Password
POST /api/accounts/reset-password/

Request:
{
  "email": "author@example.com",
  "otp": "123456",
  "new_password": "NewStrongPass123"
}

Notes:
- OTP is 6 digits.
- New password must pass Django password validators.
- Current throttle defaults: 5 requests/hour.

Submission Actions

62. Final Submit Manuscript
POST /api/journals/submissions/{submission_id}/submit/

Requirements:
- article_type selected
- required submission files uploaded
- title, abstract, keywords completed
- at least one author added
- open_access selected
- at least one classification selected
- at least one additional information field completed
- ethics_accepted true

63. Withdraw Submission
POST /api/journals/submissions/{submission_id}/withdraw/

64. Resubmit Revised Manuscript
POST /api/journals/submissions/{submission_id}/resubmit/

Allowed only when the current submission status is:
- minor_revision
- major_revision

If the submission is not in one of these statuses, the API returns:
HTTP 400 Bad Request
{
  "detail": "Only submissions requiring minor or major revision can be resubmitted."
}

Testing note:
- Until an editor decision API is implemented, set the submission status to minor_revision or major_revision using Django admin or Django shell before testing this endpoint.
- On successful resubmission, the API creates a new submission version and changes the submission status back to submitted.

Body type:
multipart/form-data

Fields:
- manuscript_file: revised_manuscript.pdf
- revision_notes: Updated as requested.

PowerShell curl example:
curl.exe -X POST "http://127.0.0.1:8000/api/journals/submissions/1/resubmit/" `
  -H "Authorization: Bearer <access_token>" `
  -F "manuscript_file=@C:\path\to\revised_manuscript.pdf" `
  -F "revision_notes=Updated as requested."
